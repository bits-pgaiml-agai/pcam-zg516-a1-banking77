HOW TO RUN IN GOOGLE COLAB
1. Open https://colab.research.google.com/ and choose Upload notebook.
2. Upload BANKING77_GenAI_Assistant.ipynb.
3. Choose Runtime > Change runtime type > T4 GPU, then Save.
4. Choose Runtime > Run all. The first cell installs pinned Python dependencies.
   If Colab asks for a runtime restart after installation, restart and run all.
5. The notebook downloads the public dataset CSVs at a fixed commit and the
   Qwen2.5-1.5B-Instruct model at a fixed revision. No bank credentials are used.
6. Open the Files sidebar. Generated evidence is in banking77_baseline_outputs/.
   Download banking77_baseline_outputs.zip created by the final cell.

DEFAULT RUN
Baseline mode runs data preparation, the three E1 generations, output validation,
and a direct synthetic tool invocation. Team generation experiments are disabled
by default so the notebook provides a small, reviewable handoff.
CPU execution works but can be much slower than a Colab GPU. Initial model
download is about 3.1 GB; inference memory depends on dtype and device.

DATA AND SAMPLING
The source has 10,003 training rows and 3,080 official test rows with 77 intents.
After normalized duplicate and cross-split overlap removal, 9,992 training rows
remain. A stratified split produces 8,992 working training and 1,000 validation
rows. The 77-row pool contains one training example per intent. Only four pool
examples enter a few-shot prompt; the entire pool is not pasted into the prompt.
The 40-row development pilot and 40-row final-test pilot each cover the same 40
intents with one example per intent. They cannot support claims about all 77
classes. The E1 baseline uses three of the development examples.

Prompt variants and decoding comparisons use development data. The official
test data is used only for optional final inference after design choices are
fixed. Reading test text keys for duplicate auditing does not use test labels
or test model results to tune the prompts. The pilot class list is seeded.

TEAM HANDOFF

the 40-row pilot is used. Full evaluation can be lengthy on a small runtime.
